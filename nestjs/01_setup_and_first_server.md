# 01 — Setup and First Server

> **Goal:** Install the Nest CLI, scaffold a new application, understand the core file layout, run the development server with hot-reload, and learn the bootstrap flow.

---

## 1. Scaffold a Nest.js app using the CLI — mental model + working code

A Nest.js application starts with the `@nestjs/cli` tool. The CLI scaffolds a pre-configured project containing TypeScript compilation configs, linting, formatting, testing setups, and a standard module structure.

### Setup and Scaffolding

First, ensure you have Node.js (v18+) and npm installed.

```bash
# Install the Nest CLI globally
npm install -g @nestjs/cli

# Generate a new project named "hello-nest"
nest new hello-nest --package-manager=npm
```

This commands builds the following folder structure:

```text
hello-nest/
├── src/
│   ├── main.ts              # Entry point. Bootstraps the Nest app instance.
│   ├── app.module.ts        # The root module of the application.
│   ├── app.controller.ts    # A basic HTTP controller with a single route.
│   ├── app.service.ts       # A basic service with a single function.
│   └── app.controller.spec.ts  # Unit tests for the app controller.
├── test/                    # E2E test files
├── tsconfig.json            # TypeScript configuration
├── package.json             # App dependencies and run scripts
└── nest-cli.json            # Configuration for the Nest CLI
```

### Running the Server

Change directory into your new app and boot the dev server:

```bash
cd hello-nest
npm run start:dev
```

This starts the application in **watch mode** (`nest start --watch`), which watches files and automatically recompiles TypeScript on changes.

You can verify the running server with `curl`:

```bash
curl -i http://localhost:3000/
# HTTP/1.1 200 OK
# Content-Type: text/html; charset=utf-8
# Content-Length: 12
# Hello World!
```

## 2. Walkthrough of Core Files

At startup, Nest.js runs the code in `src/main.ts`. Let's break down each file generated by the CLI.

### `src/main.ts` — The Bootstrapper

This file is responsible for initializing the HTTP listener.

```typescript
// src/main.ts
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
  // 1. Create a Nest application instance using the root AppModule
  const app = await NestFactory.create(AppModule);
  
  // 2. Start the HTTP server on port 3000
  await app.listen(process.env.PORT ?? 3000);
}
bootstrap();
```

- `NestFactory` is a helper class exposing static methods to instantiate applications.
- `NestFactory.create(AppModule)` initializes the Dependency Injection container, compiles modules, and binds routes.

### `src/app.module.ts` — The Root Module

Every Nest.js application must have a root module, which serves as the starting point for Nest to build the application graph.

```typescript
// src/app.module.ts
import { Module } from '@nestjs/common';
import { AppController } from './app.controller';
import { AppService } from './app.service';

@Module({
  imports: [],
  controllers: [AppController],
  providers: [AppService],
})
export class AppModule {}
```

- `@Module()` is a decorator that attaches metadata to the class, telling Nest which controllers and providers to instantiate.

### `src/app.controller.ts` — The Route Handler

Controllers handle incoming HTTP requests and map them to handler functions.

```typescript
// src/app.controller.ts
import { Controller, Get } from '@nestjs/common';
import { AppService } from './app.service';

@Controller()
export class AppController {
  // Constructor injection: Nest resolves and provides AppService automatically
  constructor(private readonly appService: AppService) {}

  @Get()
  getHello(): string {
    return this.appService.getHello();
  }
}
```

- `@Controller()` declares that this class is responsible for routing.
- `@Get()` maps GET requests on `/` to the `getHello()` handler.

### `src/app.service.ts` — The Service

Services contain the business logic. They are decorated with `@Injectable()` so they can be managed by the Nest DI container.

```typescript
// src/app.service.ts
import { Injectable } from '@nestjs/common';

@Injectable()
export class AppService {
  getHello(): string {
    return 'Hello World!';
  }
}
```

## 3. Nest CLI Generators

One of the CLI's biggest strengths is generating standard boilerplate. Instead of manually creating controller and service files, always use `nest generate` (or `nest g`):

```bash
# Generate a new module
nest g module users

# Generate a controller for users (places it in the users module folder)
nest g controller users

# Generate a service for users
nest g service users
```

The CLI will automatically:
1. Create the files under `src/users/`.
2. Add the controller and service to `users.module.ts`.
3. Import `UsersModule` into the root `AppModule` imports array.

This ensures your project layout remains perfectly formatted and wired up.

## 4. Practical Application — Fastify Swap

By default, Nest uses the **Express** HTTP server. Swapping to **Fastify** is a common choice for high-performance microservices.

Let's see how easy it is to swap the underlying platform inside `src/main.ts`:

### Install Fastify Adapter

```bash
npm i --save @nestjs/platform-fastify
```

### Update `src/main.ts`

```typescript
// src/main.ts
import { NestFactory } from '@nestjs/core';
import { FastifyAdapter, NestFastifyApplication } from '@nestjs/platform-fastify';
import { AppModule } from './app.module';

async function bootstrap() {
  // Use NestFastifyApplication type and FastifyAdapter instance
  const app = await NestFactory.create<NestFastifyApplication>(
    AppModule,
    new FastifyAdapter()
  );
  
  await app.listen(process.env.PORT ?? 3000, '0.0.0.0');
  console.log(`Application is running on: ${await app.getUrl()}`);
}
bootstrap();
```

*Note: When running Fastify, you must pass `'0.0.0.0'` to `app.listen()` to allow external connections, especially inside Docker containers.*

## 5. Common mistakes & gotchas

- **Manually writing files and forgetting to wire them.** If you create a service manually but forget to list it in the `@Module({ providers: [...] })` array, Nest will throw a runtime dependency resolution error: `Nest can't resolve dependencies of...`. Always use `nest g` to avoid this.
- **Forgetting to install global dependencies.** If running `nest` throws a command not found error, run it using npx instead: `npx @nestjs/cli new hello-nest`.
- **Not committing the `nest-cli.json` file.** This configuration file is critical for Nest to build and run your TypeScript project. Never ignore it in Git.

## 🎯 Key Takeaways & Interview Q&A

### Key Takeaways
1. **Nest CLI is non-negotiable.** It enforces file structure naming conventions and automatically updates dependencies.
2. **`main.ts` is the single entry point.** It handles Express/Fastify configuration, global filters/pipes, and ports.
3. **TypeScript decorators are structural code.** They register metadata in memory for Nest to read.
4. **AppModule wraps everything.** Every feature module must be loaded into AppModule.

### Interview Q&A

- **Q: How does Nest.js boot, and what is the role of `main.ts`?**
  → Nest boots by executing `main.ts`, which calls `NestFactory.create(AppModule)`. This loads the root module, resolves the dependency injection tree, maps controllers to HTTP endpoints, and starts the server instance.

- **Q: How do you configure Nest.js to use Fastify instead of Express?**
  → Install `@nestjs/platform-fastify`, pass `new FastifyAdapter()` as the second argument to `NestFactory.create`, and assert the application type as `NestFastifyApplication` in `main.ts`.

- **Q: Why does Nest CLI generate a `nest-cli.json` file?**
  → It configures build options, compiler options (like assets management, watch mode, custom decorators plugins), and metadata directories to build the TS output into target JS correctly.
