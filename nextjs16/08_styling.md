# 08 — Styling

> **Goal:** Configure and apply the optimal styling setups in Next.js 16 — CSS Modules, Tailwind CSS v4 (CSS-native config), and zero-runtime CSS-in-JS — and understand structural styling constraints inside Server Components.

---

## 1. Concept — Styling Frameworks

Three styling approaches integrate natively with the Next.js 16 App Router:

1. **Global CSS** — Imported once in the root layout, applying style declarations globally.
2. **CSS Modules** — Styles scoped to individual files (`Component.module.css`). Hashed class names prevent collisions.
3. **Tailwind CSS v4** — Utility classes. Next.js 16 sets up Tailwind CSS v4 with CSS-native configurations by default.

```css
/* src/app/globals.css */
@import "tailwindcss";

@theme {
  --color-background: #ffffff;
  --color-foreground: #000000;
}

body {
  background: var(--color-background);
  color: var(--color-foreground);
}
```

```tsx
// src/app/layout.tsx
import "./globals.css";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}
```

### CSS Modules

```css
/* src/components/Button.module.css */
.button {
  background: black;
  color: white;
  padding: 0.5rem 1rem;
  border-radius: 0.25rem;
}
.button:hover {
  opacity: 0.9;
}
```

```tsx
// src/components/Button.tsx
import styles from "./Button.module.css";

export function Button({ children }: { children: React.ReactNode }) {
  return <button className={styles.button}>{children}</button>;
}
```

CSS Modules are parsed during Turbopack compilation. Class names are hashed (e.g., `Button_button__c4f5a`) to prevent style leaks across modules.

---

## 2. Mechanism — Next.js CSS Loading

During compilation:
- **`globals.css`** is bundled and added via a standard `<link rel="stylesheet">` tag in the rendered page head.
- **CSS Modules** generate hashed mappings. Turbopack compiles them into route-specific CSS chunks so that pages don't load styling rules for components they don't render.
- **Tailwind CSS v4** uses a compiler that scans your codebase, extracts active utilities, and injects only the compiled rules.

### CSS-in-JS and RSC Boundaries

Server Components render entirely on the server and ship zero javascript bundle overhead to the client. This restricts run-time CSS-in-JS tools (like classic `styled-components` or `Emotion`) which dynamically inject `<style>` blocks into the client DOM at runtime.

If you choose CSS-in-JS:
- Use build-time compilation libraries (like `vanilla-extract` or `StyleX`) which generate static CSS at build-time.
- Use run-time tools ONLY within Client Components, wrapping them in styling providers (registry pattern).

## 3. Tailwind CSS v4 (CSS-Native Configuration)

Next.js 16 projects ship with **Tailwind CSS v4**, which removes the need for JS-based configurations (`tailwind.config.js`). Theme parameters are written directly in the CSS file:

```css
/* src/app/globals.css */
@import "tailwindcss";

@theme {
  --color-brand-500: #6366f1;
  --color-brand-700: #4338ca;
  --font-display: "Outfit", sans-serif;
}
```

Utility classes (like `text-brand-500` or `font-display`) are automatically generated by Tailwind's compiler.

### 3.1 Conditional Class Handling with `clsx` and `tailwind-merge`

To combine conditional styles cleanly, create a utility using `clsx` and `tailwind-merge`:

```typescript
// src/lib/cn.ts
import { clsx, type ClassValue } from "clsx";
import { twMerge } from "tailwind-merge";

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}
```

```tsx
import { cn } from "@/lib/cn";

export function AlertButton({ primary, disabled }: { primary?: boolean; disabled?: boolean }) {
  return (
    <button
      className={cn(
        "rounded px-4 py-2 text-sm transition-colors",
        primary ? "bg-brand-500 text-white" : "bg-neutral-200 text-black",
        disabled && "opacity-50 cursor-not-allowed"
      )}
    >
      Submit
    </button>
  );
}
```

`twMerge` ensures conflicting styles (like `px-2 px-4`) resolve correctly to the final override.

### 3.2 Variants with `class-variance-authority` (CVA)

```tsx
// src/components/ui/Button.tsx
import { cva, type VariantProps } from "class-variance-authority";
import { cn } from "@/lib/cn";

const buttonVariants = cva(
  "inline-flex items-center justify-center rounded font-medium transition-colors focus:outline-none focus:ring-2",
  {
    variants: {
      intent: {
        primary: "bg-brand-500 text-white hover:bg-brand-700",
        outline: "border border-neutral-300 hover:bg-neutral-100",
      },
      size: {
        sm: "h-8 px-3 text-sm",
        md: "h-10 px-4",
      },
    },
    defaultVariants: { intent: "primary", size: "md" },
  }
);

interface ButtonProps extends React.ButtonHTMLAttributes<HTMLButtonElement>, VariantProps<typeof buttonVariants> {}

export function Button({ intent, size, className, ...props }: ButtonProps) {
  return <button className={cn(buttonVariants({ intent, size }), className)} {...props} />;
}
```

This pattern scales component design libraries efficiently while keeping them fully compatible with Server Components.

## 4. Dark Mode & Themes

Implement themes using native CSS variables to ensure zero layout-shift or hydration flicker on load:

```css
/* src/app/globals.css */
@import "tailwindcss";

:root {
  --color-bg: #ffffff;
  --color-text: #171717;
}

@media (prefers-color-scheme: dark) {
  :root {
    --color-bg: #0a0a0a;
    --color-text: #ededed;
  }
}

body {
  background-color: var(--color-bg);
  color: var(--color-text);
}
```

Use `next-themes` for manually toggled dark mode:

```tsx
// src/app/providers.tsx
"use client";
import { ThemeProvider } from "next-themes";

export function Providers({ children }: { children: React.ReactNode }) {
  return <ThemeProvider attribute="class">{children}</ThemeProvider>;
}
```

```tsx
// src/app/layout.tsx
import { Providers } from "./providers";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body>
        <Providers>{children}</Providers>
      </body>
    </html>
  );
}
```

*Note: `suppressHydrationWarning` on `<html>` prevents mismatch warnings since `next-themes` applies theme classes before React runs hydration.*

## 5. Common Mistakes & Gotchas

### Constructing Dynamic Tailwind Classes
Tailwind extracts utilities at build time by reading raw class name strings. **Never construct classes dynamically** like `bg-${color}-500`, as the compiler cannot evaluate them. Map classes explicitly instead:

```typescript
// WRONG
const buttonBg = `bg-${color}-500`;

// CORRECT
const bgMap = {
  red: "bg-red-500",
  blue: "bg-blue-500",
};
const buttonBg = bgMap[color];
```

### Leaking Global Imports
Only import global stylesheets inside the root layout file. Importing global styles at lower segment layers disrupts route-level chunking and increases page overhead.

---

## 🎯 Key Takeaways

- **Tailwind CSS v4 uses CSS configs:** Configurations are native CSS rules; no JS file required.
- **Component Variants:** Use `cva` combined with `cn` to manage variant-based styling clean.
- **Avoid run-time CSS-in-JS in Server Components:** Prefer static CSS, CSS modules, Tailwind, or compile-time options like vanilla-extract.
