# 02 — Tool Calling & Structured Outputs

> **Goal:** Build robust tool interfaces using Pydantic and the `@tool` decorator, bind tools to LLMs, parse tool execution requests, and enforce structured JSON outputs.

---

## 1. What is Tool Calling?

Tool calling (often called function calling) is the mechanism where an LLM determines that it needs to run an external function (e.g., query a database, search the web, calculate a number), generates the arguments for that function, and outputs them as structured JSON. 

*Crucial note:* The LLM does **not** execute the tool itself. The model outputs a request to run a tool, which your orchestrator code must execute and return the results back to the model.

```
[User Input] ──> [LLM (with Tools bound)]
                     │
                     └──> Tool Call Request: {"name": "calculate", "args": {"x": 5, "y": 10}}
                             │
[Your Code Executes Tool] ◄──┘
     │
     └──> Observation: "Result is 15" ──> [LLM (Summarizes Answer)] ──> [Final Output]
```

## 2. Defining Tools

LangChain offers two primary methods to define tools: the `@tool` decorator (ideal for functions) and subclassing `BaseModel` (ideal for complex schemas).

### Method A: The `@tool` Decorator
This is the simplest way to define a tool. LangChain parses the function name, docstring, and type annotations to generate the JSON schema required by the model provider (OpenAI, Anthropic, etc.).

```python
from langchain_core.tools import tool

@tool
def calculate_area(width: float, height: float) -> float:
    """Calculate the area of a rectangle.
    
    Args:
        width: The width of the rectangle in meters.
        height: The height of the rectangle in meters.
    """
    return width * height

# Print the tool's autogenerated schema
import json
print(json.dumps(calculate_area.args, indent=2))
```
*Tip:* Your docstring and type hints are **part of the prompt** sent to the LLM. If you write poor docstrings or omit type annotations, the LLM will fail to call your tools correctly.

### Method B: Pydantic Schemas (Complex Inputs)
For complex input schemas or strict validation rules, define a Pydantic model:

```python
from pydantic import BaseModel, Field

class DatabaseQuerySchema(BaseModel):
    query: str = Field(description="The SQL query to execute against the users table.")
    limit: int = Field(default=10, description="The maximum number of rows to return.")

@tool(args_schema=DatabaseQuerySchema)
def run_user_query(query: str, limit: int) -> str:
    """Execute a read-only SQL query on the users database."""
    # Database logic goes here
    return f"Executed query: '{query}' with limit {limit} (Mocked)"
```

## 3. Binding Tools to a Model

Once defined, you bind the tools to your model using `.bind_tools()`. This forces the model to respect the tool signatures in its system context.

```python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# Bind tools to the model
tools = [calculate_area, run_user_query]
model_with_tools = model.bind_tools(tools)

# Test invocation
response = model_with_tools.invoke("Find the area of a room that is 5m wide and 4m long.")

# Inspect the tool calls
print("Tool Calls Request:")
print(response.tool_calls)
```
Output:
```python
[{'name': 'calculate_area', 'args': {'width': 5.0, 'height': 4.0}, 'id': 'call_abc123'}]
```
Each tool call has:
*   `name`: The function name to call.
*   `args`: A dictionary of arguments.
*   `id`: The unique call ID (crucial for sending responses back).

## 4. Enforcing Structured Output

Sometimes you do not want the model to decide whether to call a tool; you just want it to return JSON matching a specific schema (e.g., sentiment analysis, entity extraction). 

Use `.with_structured_output()` to force the model to output a Pydantic model.

```python
from pydantic import BaseModel, Field
from typing import List

class FeedbackAnalysis(BaseModel):
    sentiment: str = Field(description="Must be positive, negative, or neutral.")
    key_issues: List[str] = Field(description="A list of specific complaints or issues raised.")
    priority: int = Field(description="An integer scale from 1 (low) to 5 (critical) priority.")

# Bind structured output schema to the model
structured_model = model.with_structured_output(FeedbackAnalysis)

# Run classification
analysis = structured_model.invoke(
    "The login page loads incredibly slowly on iOS, and the submit button is invisible in dark mode."
)

print(type(analysis))  # <class '__main__.FeedbackAnalysis'>
print(analysis.sentiment)   # "negative"
print(analysis.key_issues)  # ["slow login loading on iOS", "invisible submit button in dark mode"]
print(analysis.priority)    # 4
```
